# hitl-mfa-lab

Demo-tier standalone app: an agent's money movement is gated by a mock authorization policy — amount bands decide PERMIT / HITL consent / MFA step-up / hard DENY, and CIBA requests out-of-band approval on the user's own phone for a sensitive agent-initiated action, regardless of amount. Approvals are single-use, amount-bound receipts; the MFA credit has a 5-minute TTL. Standalone mock of the AI-DEMO2 HITL track (UC7/UC8/UC22, `authorizeObligations` / `hitlCredit` / CIBA services).

- Run: `./scripts/run.sh` (http://localhost:7680). Test: `npm test` (server is `node --test test/*.test.js`, a glob). Preflight: `npm run doctor`. Reset: `npm run reset`.
- Core: `server/src/policy.js` (pure `evaluateAmountPolicy`, `normalizeBands`, `classifyObligation(s)`, `createReceiptStore`, `createCibaStore`). Story data `server/src/policyData.js` with `{{castBrand}}`-style tokens filled by `cast.js` (3 vertical packs); a test fails on an undefined token. Diagram: `server/diagrams/hitl-mfa-flow.json` (diagram-studio/1).
- API: `GET/POST /api/policy` (bands; a crossing edit falls back to defaults, never wider), `POST /api/transfer` (428 human beat / 403 deny / 200 permit), `POST /api/mfa/challenge|verify` (demo OTP 123123), `POST /api/mfa/push` + `GET /api/mfa/poll/:id` + `POST /api/mfa/push/:id/respond` (mock PingID push, `server/src/push.js`: single-use amount-bound `push` credit, 60 s to answer), `POST /api/ciba/bc-authorize`, `GET /api/ciba/poll/:authReqId`, `POST /api/ciba/respond`, `GET /api/privilege/real` + `POST /api/privilege/real/call` (Real only: `server/src/privilegeReal.js`, one real MCP tools/call, key never returned/logged/traced; shared `gatewayTrace.js` vendored), `GET /api/privilege/hitl` + `POST /api/privilege/hitl/:id/decide` (mock Privilege HITL Requests; `server/src/privilege.js`: hold, PingID-confirmed decide, one-transaction check/consume, 120 s open / 90 s retry), `GET /api/runs`, `GET /api/run-observability`, `POST /api/reset`, `GET /api/info`, `POST /api/mode` (rule 19; 409 when Real unconfigured), `GET /api/health` (demo-health/1). Workspace id in `X-Workspace`.
- Decision contract (do not weaken): DENY > STEP_UP > HITL (highest gate wins); most-specific classification (HITL_CONSENT before HITL); a receipt discharges its gate for exactly ONE retried call and only at or below its bound amount; declared step-up (`ciba`/`p1mfa`/`privilege`/`pingid-push`) is amount-independent but still below a hard DENY; an unknown band value falls back to the DEFAULTS, never wider.
- Two real paths, kept apart. (1) The PRIVILEGE scenario (HITL through Privilege) DOES use PingID push, but the push is Privilege's, not the lab's: the gateway holds the call (403 `pending_approval`), Privilege asks PingID to confirm the approver (a push, or a passcode from the app; tenant MFA on), and the lab only sends the call and retries it with the approval id (PolicyGate auto-retry, 3 s). The lab's own server makes no PingID/PingOne call on this path and must not add one, and it has no device picker (the approver's check runs in Privilege and PingID). (2) The MFA and PUSH beats, when the PingOne worker is in `.env` (`HMLAB_PINGONE_*`), use the real device-authentication path in `server/src/pingoneOtp.js` (allow-listed `auth.pingone`/`api.pingone` hosts only, one challenge at a time, the code never leaves the flow): device picker, PingOne sends the code or push, and the human either approves the PingID push in the app (the page polls `GET /api/mfa/real-otp/poll`; PingOne marks the challenge COMPLETED) or types the code. MFA mints a `stepUp` credit, PUSH a `push` credit (`verify` and `poll` take `method: "pingid-push"`). Without the worker both stay the labelled mock.
- Rules that bite: loopback bind only; same-origin writes; zero outbound network (netguard); only `.example`/`.invalid` hosts in shipped text; the only outbound exceptions are owner-run Real mode (exactly the host of `HMLAB_REAL_URL`) and the PingOne worker's two hosts (netguard `allowHost`, set while Real is on, cleared by Mock); ports 7680-7689; the demo OTP and every decision value shown raw and labelled mock; `POST /api/mode` is exactly `{ source: "mock"|"real" }`.
- Web: `web/src/App.jsx` (tabs, presenter, Reset, X-Workspace via `workspace.js`), `components/PolicyGate` (bands editor, agent call with the declared step-up, consent modal + auto-retry, MFA modal, CIBA phone panel, verdict + hops), `DiagramTab` + `PatternDiagram` (from the scaffold). Colours come from `tokens.css` only. Test: `npm test -w web` (vitest + RTL, mocked fetch).
- Transfer gate tab = numbered steps: `PolicyGate` renders pick, `LiveFlow` (the lab diagram drawn from the run; `PatternDiagram` `liveStep`/`compact` props), `TokenReel` (cards from `reelCards`), result. The pure mapping from run + minted ids to arrows and cards is `web/src/liveFlow.js`. The agent bearer card is a placeholder: the lab mints no JWT.
- Trace: `server/src/trace.js` builds W3C traceparent for every mock hop in `/api/transfer` (hops differ by decision: PERMIT 2+, HITL 3, STEP_UP 3, CIBA 5).
- Run observability (rule 27): the shared panel is vendored, pinned and never edited (`web/src/run-observability/`, `server/src/runObservability.js`, `scripts/run-observability-checkPin.mjs`; re-vendor from the canonical, then re-pin). Core only: this lab reads no product logs, so no readers file, no `RUN_OBS_*`, no Docker socket (`scripts/run-observability.pin.test.mjs` pins that). The lab's half is `server/src/runLog.js`: each decision is stamped once, written as one stdout line (no word the shared matchers read; every value sanitised and masked) and kept as a row of its run (one open run per workspace and source, bounded, never evicted; an event after the verdict joins nothing). Mock rows are `simulated`, Real rows are `response` (never `logged`). Only a policy point's decision is allowed/refused (the amount-band gate, the Privilege approval check, the gateway reply); a hold, a pending human beat and the IdP's accepted MFA code are `info`; a Real call with no reply is an `info` row. An answer joins the run that asked (ids are bound when the hold or challenge is made; an answer for a closed run is stdout only); a retry after a human beat joins its run (receipt, approval, or the page's `X-Hmlab-Retry: 1`). `GET /api/run-observability` returns only a run of the current mode; the real call's answer carries `runObservability { began, recorded, afterReset }`. Page: `web/src/components/RunObs.jsx` re-reads after every write (`workspace.js` fires `hmlab-step`; the real call's automatic retry passes `announce: false` and asks only when the answer `recorded`) and once when a poll first reports a push or CIBA lapse (`api.js`); never on every poll.
