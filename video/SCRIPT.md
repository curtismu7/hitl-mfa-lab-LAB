# Script: PingID for HITL — a human approves the agent's tool call, on their phone

Written first, before any recording (video standard: every video has a script, built from the specs and docs actually read, not from memory). `captions.md` will carry the on-screen wording and must say what this script says. If a source changes, change the script, then the captions, then retake. Written 2026-11-21.

- **Format:** silent screen capture with numbered captions and four full-screen slides (opening, what is real vs simulated, the retry rule, closing), light theme, about 7 minutes. Slides and captions are read at about 4 words a second. Opens and closes with a slide.
- **Audience:** a colleague who knows what an AI agent and MCP are, but has not seen PingOne Privilege's HITL approvals or PingID used this way.
- **One idea:** when policy says a sensitive agent action needs a person, the gateway does not refuse — it holds, and the approval happens on the human's own device with PingID: a compromised browser or a rogue agent cannot self-approve.

**Wire-format note (said once, on the opening slide):** the lab's mock gateway reproduces the wire shapes from a screen recording of a real Privilege tenant (2026-11-17) — 403 with a JSON-RPC error whose data carries `pending_approval` and an instruction id — but on our own tenant those shapes are UNVERIFIED (README, LAB-UNVER). CIBA Core 1.0 is cited because the agent's retry loop mirrors the spec's poll mode (repeat the request at an interval; treat pending, expired, and denied differently), not because Privilege speaks CIBA on this hop — the hold/retry protocol here is Privilege's own (`X-Procyon-Approval-Id`), not an OAuth grant.
